# Historical production is distinct from the public runner

The paper package pins benchmark commit bef1775e7eaea6a5d5f3c41c829eb7cee55a0d9f (forecastbench-sim `main`, November 12, 2026) for its parsing and scoring code; its scoring files are byte-identical to the earlier pin 9e016b76. **That public revision is not an interchangeable producer for the paper's original trajectories.** Issue [#6](https://github.com/forecastingresearch/forecastbench-sim/issues/6) identified a vaccination scheduling mismatch in the live Starsim runner and a separate conditional question-bank import defect, both fixed in 2cd9ace6, which the pin includes. Neither path is called by the paper code.

The historical paper producer includes the previously committed timing correction at 65204aa59cfb9fa835cf5b2af8917e02e98a4f26 plus preserved local production modifications. Its source state, environment and local runner modification are in production/starsim (see production/README.md); do not infer them from the public benchmark pin. Repaired continuous truth uses a separate corrected fixed-state helper (production/starsim/fixed_state) whose source hashes and timing assertions are recorded in the frozen production plan; it reuses original model forecasts. Historical binary truth remains distinct and appendix-only.

A 2026-09-24 audit compared preserved historical caches, repaired arrays and current-manuscript inputs. Saved preintervention checkpoints agreed between the historical control and vaccination branches; repaired branches had identical preintervention prefixes and the expected uptake distinction. Current-manuscript Starsim input CSV bytes matched the frozen analysis input. Together with the corrected producer/helper provenance, this supports no numerical paper correction for the two specific issue #6 defects. It does not establish general scientific correctness, verify every original wire prompt, or replace a missing complete generation process log. No production rerun was performed for this publication.

Public legacy demo conditional artifacts are suspect/stale and are not the paper inputs. The exact number of their labels that would change requires a separately authorized regeneration; it is not established here. Live-runner fixes are handled in the benchmark repository independently. This repository only claims the analysis from the data folder, subject to the documented scientific and rendering limitations.
