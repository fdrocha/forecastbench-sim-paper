The maintained entrypoint is the fbsim-paper command (python -m fbsim_paper). The build route writes generated files into the manuscript checkout it is given, from the data folder (its manuscript inputs are datasets/paper-inputs); it never writes manuscript text. check-data and compare only read. Scientific function bodies, input panels, normalization and uncertainty methods are retained. Starsim and Micropolis numerical scoring imports the benchmark; paper scripts own selection/normalization/aggregation. FreeCiv reporting consumes existing per-item scores. The complete original coauthor source remains recoverable outside this package. Apart from the build route's generated files, the package never edits the manuscript; it never launches simulators or calls providers. The launchers, prompts and settings that produced its inputs are kept in production/ as records; they have not been rerun, and running them is a separate, manual task. Only the analysis from the data folder is claimed. Assets preserve reporting dependencies, not a promise that every legacy helper is runnable independently. Five FreeCiv run-2 scripts in assets/freeciv are retained but run by no command: make_freeciv_aggregates.py, results_table.py, run2_numbers.py, compare_runs.py and effort_compare.py. The human-pilot table has no generator in the known code homes; it is kept as authored.

The `case-study` route reads the FreeCiv and historical measles inputs, checks targets and saved scores, and writes diagnostics and plots to a new directory outside Git. It uses the offline guard and never edits the archive or manuscript; the build's case-study step copies only its plot CSV and PDF into the manuscript. Parser verification is optional and separately reported. See CALIBRATION_CASE_STUDY.md for the exploratory scope and selection limitations.
